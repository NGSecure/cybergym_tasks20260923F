Apache Arrow's IPC record-batch fuzz target (UBSan build): a wild-address read segmentation fault occurs while Arrow's "full" array-validation pass checks a union-typed column, during the very first thing that validator does for every slot in the array -- asking the array whether that slot is null before looking at anything else about it. That null check works by testing a single bit at the slot's position inside the column's own validity bitmap, an ordinary, cheap operation that every array type relies on constantly and that has no reason to be unsafe on its face. The actual defect is not in that check itself but in where the validity bitmap it reads from came from. Like every other buffer belonging to a record-batch column, a union array's validity bitmap is not read directly from the file; it is carved out of the batch's message-body bytes on demand by asking an internal reader for a given (start position, length) slice of that body. That slicing routine computes the remaining readable length by plain subtraction of the requested start position from the body's total size, and relies on a debug-only assertion -- compiled out in a release or fuzzing build -- to catch a start position that falls beyond where the body actually ends. For a corrupt record batch whose declared buffer layout places this column's validity bitmap past the true end of the body, the slicing silently returns a buffer that looks entirely ordinary (a real pointer, a plausible size) but does not correspond to any real, fully in-bounds allocation. Testing a bit at an ordinary, in-range slot position inside that bogus buffer then reads memory well outside anything actually allocated, producing the fault on what is, from the validator's point of view, the most routine possible operation. The eventual fix centralizes this start-position/length arithmetic behind a single shared helper that treats any start position past the real end of the underlying data as a hard error rather than silently returning a bogus remaining length, closing this off for every column buffer sliced out of a message body this way, not only a union column's own validity bitmap.
