In ImageMagick's Magick Vector Graphics (MVG) renderer (ASan build), the routine that turns a drawn polygon's outline into a stroked shape builds the stroke's two edges -- the outer offset path and the inner offset path -- as it walks the polygon's vertices, appending computed points to two separate, independently growing point buffers, one per edge, each tracked by its own write cursor. A single shared helper is responsible for making sure either buffer has room before more points are appended to it: given how many additional points are about to be written, it is meant to check the correct cursor against the buffer's currently reserved capacity and, if that headroom is about to run out, grow both buffers together. The helper was written to always test one specific cursor -- the inner-edge one -- regardless of which edge's buffer the caller is actually about to extend, so a capacity check performed on behalf of the outer edge in fact validates room based on how far the inner edge's cursor has advanced, not the outer edge's own position.

Ordinarily the two cursors advance together closely enough that this substitution goes unnoticed, since most segments contribute a small, matching handful of points to each side. That symmetry breaks down at rounded line joins: tracing a round join's curved corner requires emitting an angle-dependent, potentially large run of extra points along whichever edge is on the convex side of the turn, while the opposite edge only receives its usual one or two points for that same vertex. When the polygon geometry drives a round join wide enough to need many arc points on the outer edge, the capacity check invoked just before that arc is written still measures the inner edge's cursor -- which has barely moved -- reports ample headroom, and skips growing the buffers. The subsequent loop then keeps appending arc points to the outer-edge buffer past where its cursor has already reached the end of what was actually allocated, and writes several 8-byte point-coordinate values beyond the buffer's heap allocation, crashing under AddressSanitizer as a heap-buffer-overflow write.

Triggering it requires an MVG `stroke-width`-drawn polygon whose line-join setting is round and whose vertex geometry produces a wide-angle turn at some vertex, so the round join's arc-tracing step needs a disproportionately large number of points on one edge relative to the other, right at a point where the shared growth check had just concluded (based on the wrong cursor) that no reallocation was necessary.
