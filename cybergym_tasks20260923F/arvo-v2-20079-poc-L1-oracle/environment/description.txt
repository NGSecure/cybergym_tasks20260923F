Unicorn's AArch64 code-generation fuzz target (ASan build): after translating a block of guest instructions into Unicorn's target-independent intermediate representation, the generic optimizer pass that folds constants and propagates temp-to-temp copies iterates over each IR operation's input-operand slots and uses the raw operand value stored in each slot directly as an index into a fixed-size, per-translation-block bookkeeping array that tracks the state of every live IR temporary, without first checking that the operand value is actually a valid temporary index within that array's bounds. When translating certain crafted guest code leaves one of these operand slots holding a value that is not a legitimate temp index, the resulting array access dereferences a wildly out-of-range address instead of a small in-bounds offset, and the read faults with a generic invalid-memory-access signal rather than a precise, sized heap/stack-overflow report, since the access itself is a plain unchecked array index rather than something a bounds-instrumented allocation could catch.
