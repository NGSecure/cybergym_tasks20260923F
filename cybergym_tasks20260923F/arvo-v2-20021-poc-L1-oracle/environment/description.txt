harfbuzz hb-subset (ASan build): while computing which lookups to retain for a crafted font's GSUB table, harfbuzz walks a per-record table of alternate feature definitions attached to a variable-font "which feature applies under which design-space region" table, in order to collect the lookup indices that region's substitute features would pull in. Each per-region record carries a 16-bit offset to its own alternate-feature-list sub-table, and that offset had already been range-checked during the earlier sanitize pass -- but the check validated the offset relative to the address of the enclosing table that owns the whole per-region list, while the code that later actually follows the offset to read the sub-table instead computed the target address relative to the individual per-region record's own address inside that list. Because a per-region record sits partway into the table rather than at its start, adding the (validated) offset to the wrong base address lands the subsequent read a little past the true end of the heap buffer backing the sanitized table, reading two bytes that were never covered by any bounds check at all.
