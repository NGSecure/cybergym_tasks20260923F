Apache Arrow C++ (ASan build), IPC stream reader fuzz target: while reconstructing a schema from an IPC message, one of the routines that turns a raw schema field back into an Arrow field object reads that field's name out of the underlying serialized buffer without first checking whether the name is actually present -- a sibling code path for a differently-encoded kind of field does perform that check, but this one does not. A crafted schema that declares a field of the encoded kind whose name is simply omitted causes the missing check to be skipped, and the runtime's own string-length lookup then follows a pointer that was never validated, landing outside any real allocation and producing a wild-address read.
