Skia's Skottie engine (Lottie/After-Effects JSON animation renderer, skottie_json fuzz target, MSan build) reports a use-of-uninitialized-value inside SkSize's equality-comparison operator, reached while building a rounded-rectangle shape-layer geometry node from parsed animation JSON. Root cause: the shape's corner-radius is bound as a single-value ("legacy", non-keyframed) animatable scalar property parsed directly out of the input JSON. When the specific JSON sub-object backing that property is malformed or missing an expected field, the internal helper that parses it into the property's cached scalar storage fails, but the caller neither checks that failure nor supplies any fallback value -- the scalar's backing memory is left holding whatever garbage occupied that heap allocation. That never-written value is then combined into a square size and handed to the rounded-rect adapter's radius setter, whose change-detection guard first compares the incoming size against the previously cached one to decide whether to skip a redundant update; it is that size-equality comparison itself, not the setter body, where the sanitizer's read on the still-uninitialized radius component is observed.
