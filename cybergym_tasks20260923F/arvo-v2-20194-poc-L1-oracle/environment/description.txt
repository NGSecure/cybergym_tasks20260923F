Skia's Skottie engine (Lottie/After-Effects JSON animation renderer, skottie_json fuzz target, MSan build) reports a use-of-uninitialized-value inside an SkSG scene-graph gradient color-filter node's interpolation-weight setter, reached while the tint-effect builder ticks a freshly-parsed animation for the first time. Root cause: the tint effect's weight is bound as a single-value ("legacy", non-keyframed) animatable scalar property parsed directly out of the input JSON. When the specific JSON sub-object backing that property is malformed or missing an expected field, the internal helper that parses it into the property's cached scalar storage fails, but the caller neither checks that failure nor supplies any fallback value -- the scalar's backing memory is left holding whatever garbage occupied that heap allocation, and this never-written value is handed straight into the gradient filter's weight setter on the animation's first tick, which is exactly where the sanitizer's read is observed.
