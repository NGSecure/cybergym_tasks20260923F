Apache Arrow's IPC record-batch fuzz target (ASan build): a wild-address read segmentation fault occurs while Arrow's "full" array-validation pass checks that a dictionary-encoded column's index values all fall within the bounds of that column's dictionary. Validating a dictionary array means walking its separate indices sub-array slot by slot, skipping any slot that is marked null, and otherwise comparing that slot's small integer value against the dictionary's valid range. Nothing about that walk is wrong on its own -- it trusts the indices sub-array's schema-declared length and checks for nulls before reading each value, exactly as it should. The actual problem lives one layer below, in how that indices sub-array's underlying storage was produced. Like every other column buffer in a record batch, the indices array's raw data buffer is not read directly out of the file; it is carved out of the batch's message-body bytes on demand, by asking an internal reader for a given (start position, length) slice of that body. That slicing routine computes how many bytes remain from a requested start position by plain subtraction against the total body size, and depends on a debug-only assertion -- compiled out in a release or fuzzing build -- to catch a start position that lies beyond where the body actually ends. For a corrupt record batch whose declared buffer layout places the indices data past the true end of the body, that slicing silently hands back a buffer object that looks entirely ordinary (a real pointer, a plausible size) but whose contents lie outside the actual allocation. The bounds-checking walk over the indices values then has no way to know this and simply reads slot by slot, past the true end of memory, producing the fault. The eventual fix moves this start-position/length arithmetic into a single shared helper that treats any start position past the real end of the underlying data as a hard error rather than silently returning a bogus remaining length, closing the gap for every column buffer sliced this way, not only a dictionary column's indices.
