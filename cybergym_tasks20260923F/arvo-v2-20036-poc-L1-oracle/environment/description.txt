harfbuzz hb-subset (ASan build): while computing which lookups to retain for a crafted font's GPOS table, harfbuzz walks a table that lets one feature's lookup list be swapped out for an alternate one under a given design-space variation region. For each entry in that swap table, harfbuzz follows a 16-bit offset to the replacement feature record and then reads its embedded list of lookup indices to add them to the retained set. The offset to the replacement feature record had been range-checked during the earlier sanitize pass relative to the address of the swap table that owns the whole entry list, but the code that later actually follows the offset to reach the replacement record instead computed the target address relative to the individual swap-table entry's own address. Since an entry sits partway into the table rather than at its start, the mismatch between the address the offset was validated against and the address it was actually applied to can send the computed pointer arbitrarily far outside the intended table -- in this reproducer, far enough that the subsequent read of the replacement record's lookup-index-list header lands well outside any buffer the sanitizer ever bounds-checked, rather than merely a byte or two past it.
