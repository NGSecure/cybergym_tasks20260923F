harfbuzz hb-subset (ASan build): when subsetting a font's GPOS glyph-pair-adjustment lookup table, harfbuzz revalidates each retained glyph pair's value record -- including an optional embedded hinting-device-table offset -- during an earlier sanitize pass, before the same record is later followed and copied into the output font at subset time. The sanitize pass computes the target address for that offset relative to the address of the array of per-coverage-glyph sub-table pointers that the whole lookup owns, rather than relative to the individual per-glyph-pair sub-table the offset is actually defined within; the same numeric offset is therefore checked against the wrong starting address. Because any individual per-glyph-pair sub-table sits somewhere partway into that owning array rather than coinciding with its start, a crafted offset that would be out of bounds relative to the correct base can still appear in-bounds when checked against the array's base instead. When the subsetter later serializes that same record for real, it follows the identical offset from the correct (different) base and copies out a small fixed-layout device-hinting table whose declared byte length is read straight from the untrusted font bytes -- resulting in a read of many thousands of bytes past the end of the sanitized table's heap allocation.
